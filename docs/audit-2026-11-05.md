# Audit — 2026-11-05

Twenty parallel read-only audits covering edge cases, security, memory and Android
practice. Every critical/high claim below was re-checked against the source before
being written up; two claims were corrected and are listed at the end.

Legend: **verified** = confirmed by reading the code during this audit.

## 1. Critical

### 1.1 Restore destroys annotations with no confirmation — verified
`core/data/.../LibraryBackupManager.kt:91-108`, `feature/settings/.../SettingsScreen.kt:118-149`,
`core/data/.../DriveSync.kt:90`

`restoreOne` calls `deleteAllHighlights(bookId)` / `deleteAllBookmarks(bookId)` and then
re-inserts only what the file contains. The file picker path calls it directly with no
confirmation, and the sync path calls it automatically on download. A stale or wrong
backup silently erases every annotation newer than the file.

Also non-atomic: `withTransaction` wraps one book, so a failure at book N leaves books
`1..N-1` committed (`:72-86`).

Fix: confirmation sheet listing scope and counts; merge by record id + `createdAt` instead
of delete-all; one transaction for the whole restore (or staging table + swap); keep a
pre-restore snapshot for undo.

## 2. High

### 2.1 Reader session has no owner token — verified
`feature/reader/impl/.../ReaderSessionStore.kt:156-190, 216-242`, `ReaderViewModel.kt:422-470, 761-781`

`beginOpen()`/`publish()`/`clear()` mutate a singleton with no owner identity. A reader
popped mid-open still publishes, and `publish()` closes the publication belonging to the
newer session. Two live ViewModels also both collect the shared `events` flow, so taps and
progress writes can double-apply or apply to the wrong book. The `store.bookId == bookId`
guard is false while an open is in flight, so `clear()` can be skipped and `openInFlight`
stays true for the process.

Fix: return an epoch token from `beginOpen()`, no-op `publish`/`clear` unless it matches,
gate the event collector on it, and always reset transient flags in `onCleared`.

### 2.2 `SessionLost` can be dropped — verified
`ReaderSessionStore.kt:159` (`MutableSharedFlow(extraBufferCapacity = 64)`, no replay),
`ReaderHostFragment.kt:52-63`, `ReaderNavigatorHost.kt:56-79`

Emitted with `tryEmit` from `onCreate` and only consumed by a ViewModel collector that may
not be attached yet. A missed loss leaves the host refusing to re-add itself, so a
process-death restore parks on the loader.

Fix: make loss latched state (replay 1 / `StateFlow`), and read store state on VM init
rather than relying on an event.

### 2.3 Publication leaks when open is cancelled before publish — verified
`ReaderViewModel.kt:438-470`

If the coroutine is cancelled after `opener.open()` succeeds but before `store.publish()`,
no owner ever closes the publication or its SAF descriptor.

Fix: `try/finally` that closes the result whenever publish did not take ownership, or
perform the publish step under `NonCancellable`.

### 2.4 Imported copies are deleted while the UI promises they are kept — verified
`core/data/.../BookManagementUseCase.kt:59`, `feature/library/impl/src/main/res/values/strings.xml` (`library_menu_delete_body`)

For imported books the app-private copy **is** the only copy, but the confirm dialog says
"Files on disk are kept." Irreversible data loss plus a false statement.

Fix: branch the copy for imported rows ("this imported copy will be deleted"), or keep the
bytes.

### 2.5 Import leaves orphans, allows duplicates, ignores free space — verified
`core/data/.../LibraryScanUseCase.kt:146-197`

- `CancellationException` rethrown without deleting `dest`; no sweep of `books/`.
- Rows keyed by random UUID, no content hash → sharing twice duplicates the file and
  diverges progress/annotations.
- No `StatFs` precondition; a 512 MiB cap is checked only by writing.
- `MainActivity.kt:35-42` runs `handleDeepLink` without a `savedInstanceState == null`
  guard → recreation re-imports the same intent.

Fix: delete on cancel/failure in `finally`, startup sweep against the DB, stream-hash while
copying and reuse the existing row, pre-flight free space, guard deep links and record the
consumed intent.

### 2.6 Prune can wipe the library, and can silently mis-prune — verified
`core/data/.../LibraryScanUseCase.kt:108-131, 210-233`, `LinkedTreeLister.kt:80, 116-153`

- `foundIdsOf.isEmpty() && pruned.isNotEmpty()` → `deleteAllLinked()` (global, all trees).
- Hidden directories are skipped without setting `walkFailed`, so renaming a library folder
  to a dot-dir reads as "successfully empty" and feeds the wipe above.
- Nested/duplicate linked folders index the same document twice (identity is the per-tree
  document URI).
- `prunedLinked` is fine (chunked), but the FTS delete at `:230` binds **every** pruned id in
  one statement: past SQLite's variable limit the transaction throws, so the whole pass
  rolls back and every later scan fails identically.

Fix: prune per successfully walked tree; treat skipped hidden subtrees as incomplete;
reject overlapping trees and dedupe by `(authority, documentId)`; chunk the FTS delete with
the existing `DELETE_CHUNK` loop.

### 2.7 Cloud backup ships imported books and private index — verified
`app/src/main/res/xml/backup_rules.xml`, `data_extraction_rules.xml`

`<include domain="file" path="."/>` covers `filesDir/books/*.epub`, the covers dir is the
only exclusion, and the database (with full chapter text and annotations) is included.
The file's own comment claims book files are never copied by the app. This is user content
leaving the device, breaks the ~25 MB Auto Backup budget, and contradicts the privacy copy.

Fix: exclude `books` (and the FTS payload if separable) from both cloud rules; keep the
index out of transfer or rebuild it.

### 2.8 Settings backup import/export runs on the main thread — verified
`feature/settings/.../SettingsScreen.kt:118-180`

Import opens the stream, allocates an 8M-char array and performs a single `read` on the
composition dispatcher (short reads silently truncate larger backups). Export encodes the
whole library on main and puts the JSON in `EXTRA_TEXT`, which crosses the Binder limit for
annotated libraries.

Fix: `Dispatchers.IO`, loop until EOF with a byte cap and a specific "too large" message;
share a cache file through a content URI.

### 2.9 Image showcase decodes on the main thread — verified
`feature/reader/impl/.../ReaderImageShowcase.kt:43-48`, `ReaderViewModel.kt:735-742`

`LaunchedEffect` runs on the composition dispatcher; the byte read and both
`BitmapFactory` passes happen there. A full-page plate freezes the reader.

Fix: `withContext(Dispatchers.IO)` for read + decode, publish the result to state.

### 2.10 Page-slide capture retains full-screen bitmaps — verified
`feature/reader/impl/.../ReaderPageSlide.kt:99-118`, `ReaderScreen.kt:278-291`

Two full-screen RGB_565 buffers live at file scope for the process lifetime, and
`refreshSnapshot()` re-arms `outgoingPage` right after the slide, then re-captures whenever
`state.prefs` changes (the effect keys on the whole prefs object). Expect ~10 MB retained
after leaving the reader, plus churn on every brightness/font tick.

Fix: scope the pool to the reader composition with `DisposableEffect` cleanup; capture only
for the duration of a turn; key the effect on the invalidation-relevant fields.

### 2.11 Content hits are hidden when the title/author query is empty-books — verified
`feature/library/impl/.../LibraryScreen.kt:289`

The grid (and `contentHits`) only renders in the `books.isNotEmpty()` branch. A query that
matches prose but no title shows "No matches — try a different title or author" and throws
the hits away. The existing UI test always passes a book, so it never catches this.

Fix: render hits whenever they exist; only show the empty state when both are empty.

### 2.12 Content index is only built when a book is opened in the reader — verified
`feature/reader/.../ReaderViewModel.kt:539-547`; no `indexBookContent` call in the scan path

Search silently returns nothing for books the user has not opened (or opened briefly),
which is indistinguishable from "no matches" on a fresh install.

Fix: queue indexing from the scan follow-up pass with resumable progress, keep the reader
hook as a fast path.

### 2.13 FTS is broken for non-Latin scripts and diacritics — verified by agent test
`core/data/.../FtsQuery.kt`, `core/database/.../ChapterTextEntity.kt` (FTS4 `tokenize=simple`)

Terms are reduced to `isLetterOrDigit` and prefix-matched against a `simple` tokenizer:
CJK mid-phrase, Indic matras, apostrophes (`don't`), and accented uppercase all return
zero rows. Also no `notIndexed` on `book_id`/`href`, so `MATCH` yields bogus hits and
`WHERE book_id = ?` full-scans the virtual table; no `'optimize'` after bulk deletes.

Fix: `tokenize=unicode61 remove_diacritics=2` (+ explicit CJK strategy), `notIndexed` for
ids, a plain side table for delete/count, quoted terms, and periodic `optimize`.

### 2.14 Highlight creation depends on a selection that is usually gone — verified structurally
`feature/reader/.../ReaderAnnotationsController.kt:37-46`, `ReaderScreen.kt`, `ReaderHostFragment.kt:242`

The highlight is built from `nav.currentSelection()` after the user opens chrome, opens the
overflow, and confirms a dialog. The action mode is finished by then, so the save either
dead-ends on `SelectTextFirst` or persists a stale selection.

Fix: snapshot the selection locator at action-mode creation and consume that snapshot.

### 2.15 Baseline profile absent while the benchmark requires one — verified
`benchmark/.../StartupBenchmark.kt:39` (`BaselineProfileMode.Require`), no `profileinstaller`,
no app-authored `baseline-prof.txt` (only R8 merge intermediates exist)

`Require` throws when no profile is installed, so the cold-start benchmark cannot pass and
release ships fully JIT-compiled.

Fix: add a baseline-profile module + `androidx.profileinstaller`, commit the profile, keep
the benchmark on `Require` only once it exists.

### 2.16 Release workflow is not gated by tests/lint/detekt — verified
`.github/workflows/release.yml:176-193` runs only `assemble*`; `ci.yml` alone runs the gates.
It also installs `platforms;android-35`/`build-tools;35.0.0` while the project compiles with
SDK 36.

Fix: a `needs:` gate job (or a required successful CI run for the commit), and install SDK 36
from one shared toolchain action.

## 3. Medium (grouped)

**Reader correctness**
- Layout fingerprint samples the viewport only when prefs emit; rotation never re-keys, so
  landscape page counts can be persisted under the portrait key (`ReaderViewModel.kt:283-293`).
- Absolute page falls back to `0` when the locator href is not an exact `pagesByChapter` key;
  hrefs are never normalised (fragment/query) even though other call sites strip them
  (`ReaderPositionTracker.kt:170-179`).
- Chapter title picks the last TOC anchor in a file rather than the anchor at the current
  position (`:146-149`).
- Scrubber reports rendered pages, `seekTo` maps the fraction onto the position table — two
  different domains, so the drop point and settled page differ (`ReaderChrome.kt:351`,
  `ReaderPositionTracker.kt:213-226`).
- `scheduleLayoutSave` replaces the stored map with the session snapshot, so one save can
  truncate a learned 60-chapter map (`ReaderViewModel.kt:300-313`).
- `ReaderKeyInterceptor` is a single unowned handler slot; any dying reader clears it
  (`ReaderKeyInterceptor.kt:25-31`).
- `closeCurrent()` does not reset `_shownImage`, so an image overlay can survive into the
  next book.
- Navigator host guard: `findFragmentById(containerId) != null` returns early, so a leftover
  host for another book blocks attaching (the tag is per-book, so this is narrower than one
  agent claimed).

**Search**
- No content hash/`sourceModified` per indexed book: a replaced EPUB keeps stale text and
  dead hrefs (`ContentSearchUseCase.kt:19-38`).
- Round-robin is defeated by the SQL pre-limit, so a hit-heavy book monopolises results.
- `contentHits` is not keyed to the query that produced it and is never cleared on text
  change; failures collapse to "no matches".
- `snippet()` marks are empty, so the matched term is never highlighted in the row.

**Memory / jank**
- `HistoryViewModel.groupByDay` allocates a `Calendar` per book on `System.currentTimeMillis()`
  defaults, and `HistoryStatsViewModel` aggregates the whole library on the main dispatcher
  per emission (`HistoryViewModel.kt:45-78`, `HistoryStatsViewModel.kt:35-52`).
- `LibraryViewModel.uiState` combines five flows and re-copies immutable lists on Main for
  every scan tick (`LibraryViewModel.kt:106-147`).
- Library search-island animations are read in the same scope that emits the grid
  (`LibraryScreen.kt:246-266`).
- Coil's default disk cache is still constructed although every request disables it
  (`IridiumApplication.kt:27-34`).
- Cover fast path requires a live `coverPath`, so coverless books are fully re-parsed every
  scan (`LibraryScanUseCase.kt:83`).

**Security / parsing**
- XML hardening is best-effort: both SAX factories wrap every `setFeature` in
  `runCatching`/`isFeatureQuietly`, so an unsupported feature silently leaves DTD/entity
  processing on (`OpfSax.kt:68-76`, `NavSax.kt:35-49`). No secure-processing flag, no
  resolver, no DOCTYPE pre-scan.
- `@JavascriptInterface` bridge is registered for every reading-order resource with no origin
  or frame gate (`ReaderHostFragment.kt:68`); no CSP is injected, so book content can beacon
  out; no `WebSettings` are pinned (file/content access, mixed content).
- External links open the browser from content-driven navigation with no confirmation
  (`ReaderScreen.kt:127-144`).
- Native `NewStringUTF` receives bytes that are only modified-UTF-8 if the OPF was UTF-8
  (`iridium_epub.cpp:799`); invalid sequences corrupt the JSON under CheckJNI.
- No spine/manifest element caps in the JVM engine (`OpfSax.kt`), unlike the native core.
- No `try/catch` at JNI entry points: `bad_alloc` from a large inflate terminates the process.
- `ChapterIndexer` reads with the 64 MB default and only then rejects >4 MB
  (`ChapterIndexer.kt:57-59`), and decodes as UTF-8 ignoring the declared encoding.
- `HtmlText` scans to end-of-input per unclosed skipped tag (quadratic on hostile input).

**Build / practice / tests**
- No `room-testing` dependency and no migration test despite six schema versions and five
  auto-migrations.
- No `src/androidTest` anywhere, yet every module declares the instrumentation runner; the
  first instrumentation test will fail with "instrumentation not found".
- `TestDispatcherRule` defaults to `UnconfinedTestDispatcher`; no test exercises debounce or
  coalescing with `advanceTimeBy`.
- Lint never runs with `checkDependencies`, `warningsAsErrors` or a baseline; only `:app` is
  linted.
- `-keep class org.readium.** { *; }` disables shrinking/obfuscation for the largest dependency;
  no `mapping.txt` is uploaded, so release stack traces are unrecoverable.
- `getAll()` pulls every `tocJson` per scan; `chapter_layouts` rows are never deleted with a
  book (`ChapterLayoutDao.deleteForBook` has no caller).
- `SettingsViewModel`/`IridiumAppViewModel` `combine` + `@Suppress("UNCHECKED_CAST")` with
  `args[i] as T` — reordering arguments compiles and throws at runtime.
- Five user-facing strings are built inside ViewModels; several more are inline in UI code.
- `catch` on the outermost settings flow terminates the flow permanently after one error.

**Accessibility / i18n**
- Reader scrubber `Slider` has no name or state description; the counter is bare `"12 / 173"`.
- Theme swatches announce "Selected" for every swatch and nothing for unselected ones.
- Page-turn cross-slide ignores Calm mode and animator scale; slider track runs a perpetual
  wave animation regardless of motion settings.
- Image showcase has no alt text, no `onClickLabel`, and no back handling.
- RTL: tap zones and slide direction are never mirrored; "Left" is used instead of "Start".

## 4. Corrected agent claims

- **Navigator host tag is not fixed.** It is `iridium_reader_$bookId`. The real risk is the
  `findFragmentById(containerId)` early return, which is narrower.
- **`SessionLost` is not a `replay = 0` `SharedFlow` by type alone.** The flow is
  `MutableSharedFlow(extraBufferCapacity = 64)` with default `replay = 0`, which still drops
  emissions with no subscriber — the finding stands, but the detail is "no replay", not
  "replay = 0 explicitly".

## 5. Plan

Ordered by risk. Each phase is independently shippable and gated by
`testDebugUnitTest` + `detekt` + `lint` + an emulator flow.

### Phase 0 — stop the data loss (highest value, small diffs)
1. Restore: confirmation sheet, merge instead of delete-all, single transaction, undo snapshot.
2. Remove-book copy: branch the string for imported rows.
3. Import: delete on cancel/failure, `finally`, startup sweep, `StatFs` pre-flight, deep-link
   `savedInstanceState` guard + consumed-intent record.
4. Import dedupe by content hash.
5. Prune: per-tree scoping, hidden-subtree = incomplete, dedupe nested trees, chunk the FTS
   delete.
6. Backup rules: exclude `books`; document what does travel.

Gate: new unit tests for cancel/partial import, prune scoping, restore merge/idempotency;
emulator flow: import → cancel → rescan → remove → restore.

### Phase 1 — reader session and pagination correctness
1. Session token + latched `SessionLost` + unconditional transient reset in `onCleared`.
2. Close the publication when publish is cancelled.
3. Host attach: verify identity, don't trust any fragment in the container.
4. Normalise hrefs once; stop falling back to `0`.
5. Include viewport in the layout fingerprint; merge layout saves instead of replacing.
6. Selection snapshot at action-mode creation; run annotation writes through `safeCatching`.
7. Scrubber: one domain for seek + counter; surface "positions not ready".

Gate: unit tests for token races, refused turns, href normalisation, layout-key changes,
selection snapshot; device audit with `scripts/page-number-audit.sh`.

### Phase 2 — search that actually works
1. Index on scan with resumable progress and an `indexed/total` signal.
2. `unicode61 remove_diacritics=2`, `notIndexed`, side table, quoted terms, `optimize`.
3. Render hits in the empty branch; carry `(query, hits)` together; clear on text change.
4. Store `sourceModified`/hash per indexed book and re-index on change.
5. Snippet delimiters + bounded length; relevance ordering within a book.

Gate: tokenizer tests per script, empty-books-with-hits UI test, re-index-on-change test.

### Phase 3 — memory, jank, IO
1. Showcase decode off main with an explicit error state.
2. Slide buffers scoped to the reader; capture only during a turn; key the snapshot effect on
   the fields that matter.
3. Settings backup IO off main + content-URI sharing.
4. History aggregation off main with injected clock; library state copy hoisted; island
   animations isolated from the grid scope.
5. Coil disk cache disabled explicitly; coverless fast path.

Gate: `dumpsys meminfo` before/after a reader session, macrobenchmark frames, StrictMode in
debug during the flows above.

### Phase 4 — hostile input hardening
1. SAX: fail closed (pre-scan for DOCTYPE/ENTITY, secure processing, empty resolver).
2. Element caps in the JVM engine; cap entry count/name bytes in `ZipArchive`.
3. JNI: `try/catch` at entry points; UTF-8→UTF-16 conversion instead of `NewStringUTF`.
4. `ChapterIndexer`: pass the byte cap through to `read`, sniff the declared encoding.
5. `HtmlText`: single forward cursor.
6. WebView: scope the JS bridge to the main frame + `readium` origin, inject CSP, pin
   `WebSettings`, require a gesture before external navigation.

Gate: fuzz-style unit tests with malformed archives, a real malformed-EPUB fixture in
`epub-engine` tests, and an emulator open of a crafted file.

### Phase 5 — build, tests, platform practice
1. Baseline-profile module + `profileinstaller`; then keep `BaselineProfileMode.Require`.
2. Release workflow gate job; SDK 36 toolchain in one shared action.
3. `mapping.txt` artifact upload.
4. `room-testing` + migration chain tests; `androidTest` source set + runner dependency;
   `TestDispatcherRule` → `StandardTestDispatcher` with debounce tests.
5. Lint: `checkDependencies`, `warningsAsErrors`, baseline; per-module lint in CI.
6. Narrow the Readium keep rules; verify with APK size + release benchmark.
7. Remove `args[i] as T` combines; move user-facing strings into resources; make the settings
   `catch` local.
8. Configuration cache + dependency verification (follow-ups, lower priority).

Gate: `./gradlew test detekt lint` green across modules, release build installs and reads a
book, benchmark runs with the profile in place.

### Phase 6 — accessibility and product polish
1. Scrubber semantics + `reader_position_counter`/`reader_scrubber_action` resources.
2. Per-theme swatch labels and `selected` semantics.
3. Motion gating for page turns and slider waves.
4. Showcase alt text, click label, back handling.
5. Extract remaining inline strings; locale-aware date/percent/duration formatting.
6. RTL tap zones and slide direction; 48 dp destructive targets.
7. Keep `scripts/page-number-audit.sh` in the loop for reader regressions.

Gate: TalkBack pass over library/reader/settings, 200% font-scale pass, RTL layout pass.
